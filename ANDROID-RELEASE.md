# Android release preparation

## Current state

- The Capacitor Android project is generated by GitHub Actions.
- The debug APK and unsigned release AAB are build artifacts for testing only.
- `.github/workflows/android-release.yml` is prepared to build a signed APK and AAB when the owner supplies a private upload keystore and its secrets.
- The release configuration script sets Android `compileSdkVersion` and `targetSdkVersion` to API 36. The generated bundle must still be checked after the build.
- Native Android push uses Firebase Cloud Messaging. A signed release now requires the Firebase Android client file `google-services.json` in the repository root.
- The signed workflow has not been run because no signing key or GitHub signing secrets are available to this project session.
- A successful signed build is not the same as Google Play approval or publication.

## Create a private upload keystore once

On a trusted Windows computer with Java/keytool installed, open PowerShell in a private folder and run:

```powershell
keytool -genkeypair -v -keystore takeaways-tonight-upload.jks -keyalg RSA -keysize 2048 -validity 10000 -alias takeaways-tonight
```

Choose a strong unique keystore password and key password. Keep the .jks file and passwords in a secure offline backup. Never upload the keystore to this GitHub repository, email it, or share it in ChatGPT. Losing the original signing key can prevent future updates if it is the key used for the Play app.

Convert the keystore file to Base64 in PowerShell:

```powershell
[Convert]::ToBase64String([IO.File]::ReadAllBytes("takeaways-tonight-upload.jks")) | Set-Clipboard
```

## Add GitHub Actions repository secrets

In the repository open **Settings → Secrets and variables → Actions → New repository secret** and add:

| Secret name | Value |
|---|---|
| `ANDROID_KEYSTORE_BASE64` | Base64 text copied from the command above |
| `ANDROID_KEYSTORE_PASSWORD` | Keystore password |
| `ANDROID_KEY_ALIAS` | `takeaways-tonight` (or the alias chosen with keytool) |
| `ANDROID_KEY_PASSWORD` | Key password |

Do not paste any of these values into a chat, source file, issue or workflow log.

## Build a signed release

1. Open **Actions → Build signed Takeaways Tonight Android release**.
2. Choose **Run workflow**.
3. Start with version code `1` and version name `1.0.0` only if this is the first Play Store upload. Every later Play upload needs a higher version code.
4. Download the workflow artifact named `takeaways-tonight-signed-android-...`.
5. Keep the signed AAB private until the Play Console listing, privacy details, app access and content rating are ready.

The workflow validates the source, creates the Capacitor Android project, injects signing configuration only in the temporary build runner, builds the release APK/AAB and verifies the AAB signature. It does not commit the keystore or passwords.

## Firebase setup for background order notifications

Complete the steps in [PUSH-NOTIFICATIONS-SETUP.md](PUSH-NOTIFICATIONS-SETUP.md) before the signed release. In summary, register package `za.co.takeawaystonight.app` in Firebase, add `google-services.json` to the repository root, and store the Firebase service-account JSON as the Supabase Edge Function secret `FIREBASE_SERVICE_ACCOUNT_JSON`. Never commit the service-account private key. Test notifications on a real Android device with the app closed before calling background push operational.

## Before Google Play submission

- Test the signed APK on real Android devices and different screen sizes.
- Create/verify the Play Console developer account and complete identity verification.
- Add final app icon, screenshots, feature graphic, short/full descriptions and support contact.
- Publish a final privacy policy and complete Data safety, app access and content-rating declarations truthfully.
- Verify target API 36 or higher in the generated AAB and confirm the current target API requirement in Play Console at submission time.
- Test install, launch, navigation, basket, WhatsApp hand-off, external links and offline/recovery behavior.
- Remove demo listings and confirm real partner permissions before public commercial promotion.
- Submit the AAB through Play Console; review and approval are controlled by Google.

## Versioning rule

Never reuse or lower an Android version code for an update. Keep a secure record of the upload keystore, alias, passwords and last Play version code. The upload key is a critical business asset.
